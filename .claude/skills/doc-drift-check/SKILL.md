# Doc Drift Check

**이 스킬이 있는 이유는 주석과 문서가 코드와 따로 썩기 때문이다.** 컴파일러도 테스트도
이것들을 읽지 않아서, 이름을 바꾼 PR 은 초록불인 채로 거짓말을 남긴다.

**판정 기준은 여기 없다.** 주석은 루트 `AGENTS.md` §6, `AGENTS.md` 자체는 §7, 기능 문서는
`docs/AGENTS.md` 가 단일 진원지다. 시작할 때 해당하는 것을 읽는다. 아래는 **무엇을 빠뜨리지
않고 훑는가**에 대한 것이다.

§1·§2·§5 는 **이미 있는 거짓**을 찾고, §3·§4·§6 은 **새로 들어오는 위반**을 막는다. 여섯 게이트를
모두 돈다 — 한 게이트가 0건이어도 다른 게이트가 잡는 것은 종류가 다르다.

## 0. 범위 확정

커밋된 것과 아직 커밋 안 된 것을 **모두** 본다. 다음 단계의 모든 명령은 이 `BASE` 를 쓴다.

```bash
BASE_REF=$(git symbolic-ref -q --short refs/remotes/origin/HEAD || echo origin/main)
BASE=$(git merge-base HEAD "$BASE_REF")
git diff --stat $BASE
git status --porcelain
```

리뷰 대상은 diff 가 건드린 모듈뿐이다 — 그 모듈들의 `AGENTS.md` 도 §8 모듈 맵대로 읽는다.
기능의 동작·정책·제약을 건드렸으면 **그 기능의 `docs/features/` 문서도** 읽는다(§5).

## 1. 낡은 참조 — diff 가 가리키는 것

**리팩터 PR 에서 찾기 어려운 결함이다.** 사라진 이름은 코드에서는 컴파일러가 잡지만
주석·문서에서는 아무도 잡지 않는다.

먼저 **사라진 이름과 옛 경로**를 뽑는다. Kotlin 과 Swift 선언을 함께 본다.

`protocol` 과 `extension` 은 **일부러 넣지 않았다.** 둘 다 영어 산문에 흔한 단어라 주석과
문서의 평범한 문장을 선언으로 오인한다("the extension is named", "protocol constants and
DTOs"). 그리고 얻는 것이 없다 — 인터페이스는 Kotlin 이 소유하고 Swift 는 그것을 구현하므로
Swift 쪽 `protocol` 선언이 없고, `extension` 이 확장하는 타입은 그 타입의 원 선언으로 이미
잡힌다. 브릿지 방향이 바뀌어 Swift 가 자기 `protocol` 을 갖게 되면 그때 넣는다.

**셸 함수에 위치 인자를 받지 않는다.** 이 파일은 스킬 인자와 함께 주입되므로 위치 인자 표기가
그 자리에서 인자 문자열로 치환되어 읽힌다 — 그대로 실행하면 아무것도 매칭되지 않고 **게이트가
조용히 0건으로 통과한다.** 미탐 중에서도 최악이라 한쪽씩 함수를 따로 둔다.

```bash
DECL='\b(class|interface|object|enum|fun|func|val|var|typealias|struct) +[A-Za-z_][A-Za-z0-9_]*'
removed() { git diff $BASE -U0 -M | grep '^-' | grep -oE "$DECL" | awk '{print $NF}' | sort -u; }
added()   { git diff $BASE -U0 -M | grep '^+' | grep -oE "$DECL" | awk '{print $NF}' | sort -u; }

# 선언이 지워진 이름(= 왼쪽에만 있는 이름)
comm -23 <(removed) <(added)

# 옮겨지거나 지워진 파일·디렉터리
git diff $BASE -M --name-status --diff-filter=RD
```

후보 하나하나를 **저장소 전체**에서 Grep 한다. 변경된 파일만 보면 안 된다 — 낡은 참조는 손대지
않은 파일에 있다.

- 모든 `.md`(루트·모듈 `AGENTS.md`, `.claude/`, `docs/` 포함)
- 주석 줄: `(//|/\*|^\s*\*|#|<!--)` 가 앞에 오는 줄
- 빌드·설정 파일의 주석과 문자열, Manifest·plist·Xcode 설정

**이름만 보지 않는다.** 모듈 경로, Gradle 태스크 이름, 폴더 구조, 레이어 배치 설명도 같이
바뀐다 — 구조를 옮긴 PR 이면 `.md` 의 표와 경로 prefix 를 직접 대조한다.

> **후보를 좁히지 않는다.** 내부 선언이나 "문서에 쓸 일 없어 보이는" 이름을 미리 걸러내고
> 싶어지지만, Grep 은 자동이고 0건이면 즉시 끝나 **오탐 비용이 거의 없다.** 반대로 하나를
> 놓치면 거짓이 그대로 남는다 — `internal` 선언도 문서에 인용된다. 가시성·종류로 거르지 않는다.

> 기댓값은 **0건**이다. 하나라도 걸리면 그 PR 은 끝난 것이 아니다.

## 2. 낡은 주장 — diff 가 가리키지 않는 것

**가장 오래 살아남는 거짓이다.** 선언도 경로도 바뀌지 않았는데 문서가 틀려진 경우다 — 세상이
바뀌었거나, 애초에 사실이 아니었다. diff 에 단서가 없으므로 **문서를 직접 읽어 대조한다.**

**(가) 시간·상태 표현.** 문서가 "지금 어떤 상태인지" 를 주장하는 자리다.

```bash
grep -rnE "아직|임시|예정|앞으로|나중에|더 이상|현재|지금|완료|해소|끝났|[0-9]+(개|곳|벌)" \
  --include="*.md" . | grep -v '/build/'
```

걸린 줄마다 **지금도 사실인지** 확인한다. "임시" 가 영구가 되고, "아직 안 된다" 가 되고, 개수가
늘어난다. 오탐이 많은 게이트이므로 0건이 통과 기준이 아니다 — **전부 확인했음**이 기준이다.

**(나) 문서가 가리키는 대상이 실재하는가.** 백틱 안의 경로·파일·태스크·라이브러리를 뽑아
하나씩 확인한다. **변경된 문서만 보지 않는다** — 애초에 없는 것을 가리키는 문장은 어느 diff 에도
나타나지 않는다.

- 저장소 경로·파일: 그대로 존재 확인
- **모듈 안의 패키지 경로는 루트 기준이 아니다.** 그 모듈 소스셋 안에서 찾는다 — 루트에서
  찾으면 실재하는 패키지가 전부 "없음" 으로 나온다
- Gradle 태스크: `./gradlew.bat <task> --dry-run` 으로 존재 확인
- 의존 라이브러리: 버전 카탈로그와 빌드 파일에 실제로 있는지

**(다) 다른 문서와 어긋나지 않는가.** 같은 사실을 두 문서가 말하면 한쪽만 고쳐져 있다. 모듈
문서가 루트 `AGENTS.md` 의 절을 인용하면 그 절 번호와 제목이 맞는지 본다.

## 3. 새로 넣은 주석 — §6 게이트

추가된 주석 줄만 모아 §6 으로 한 줄씩 심사한다.

```bash
git diff $BASE -U0 | grep -E '^\+' | grep -E '^\+\s*(//|/\*|\*|#|<!--)'
```

§6 이 **남기라고 한 네 가지**가 아니면 지운다. 특히 자주 자라는 쪽:

- 이름·시그니처가 이미 말하는 것
- 결정 기록, 고려한 대안, 전에 어떤 코드였는지
- 테스트가 고정한 것의 재진술, 테스트로의 교차 참조
- "두 플랫폼이 X 해야 한다" — 주석이 아니라 **공유되는 한 자리**다
- 빌드가 대조할 수 있는 복제 값 — 주석이 아니라 **빌드**다
- 세 줄 넘는 KDoc — 이유를 말할 수 없으면 줄인다

지우지 않고 **옮기는** 판정이 나오면(테스트·빌드·공유 상수) 그 작업까지 이 PR 에서 끝낸다.
옮길 수도 테스트할 수도 없는 주장은 적어 두지 말고 버린다.

## 4. `AGENTS.md` 가 바뀌었다면 — 정당성 심사

```bash
git diff $BASE -- '*AGENTS.md' CLAUDE.md
```

`AGENTS.md` 는 **절대 규칙**이라 거의 바뀌지 않아야 한다. 추가된 줄마다 이 질문 하나를 묻는다:

> **아키텍처를 바꾸지 않고도 이 문장이 틀려질 수 있는가?**

그렇다면 안티패턴이다. 처분은 **삭제 또는 일반화**다.

**(가) 특정 심볼·클래스명·파일명·위치**
이름 한 번 바꾸면 깨진다. 일반화해서 **역할·규약**으로 다시 쓴다 — `FooScreen.kt` 는 현황이고
`~Screen.kt` 는 규약이다. 목록은 폴더가 갖는다(§7).
*예외*: 아키텍처가 강제해서 아키텍처 변경 없이는 못 움직이는 자리 — 모듈 맵의 경로 prefix,
모듈 경계와 의존성 방향. 예외를 주장하려면 **빌드가 그 위치를 강제하는지** 확인한다.

**(나) 결정 기록·히스토리·진행률**
무엇을 걷어냈고 무엇을 더 이상 쓰지 않으며 전에 어디까지 갔는지는 **PR 몫이다.** 현재 코드가
최종 완성본이므로 과거는 규칙이 아니다. 지운다. 살릴 가치가 있으면 과거 서술을 **현재형 제약
한 줄**로 바꿔 쓴다 — 되돌리기 어려운 기술 선택의 당시 제약이라면 `docs/DECISIONS.md` 가 그
자리다.

**(다) 빌드·테스트가 이미 보증하는 동기화 지시**
"A 를 바꾸면 B 도 바꿔라" 는 빌드가 대조하게 만든다. 문서에는 **그 보증이 있다는 사실**만 남긴다.

## 5. 기능 문서가 거짓이 됐는가 — 동작을 바꿨다면

**§1·§2 가 못 잡는 종류다.** 이름도 경로도 그대로인데 **동작이 바뀌어** 기능 문서의 제약이
거짓이 된 경우다. 컴파일도 테스트도 통과하고 Grep 에도 걸리지 않는다.

먼저 diff 가 기능의 **동작·정책·제약**을 건드렸는지 가른다. 서식 정리나 내부 리팩터라면 이
게이트는 건너뛴다.

건드렸으면:

1. **그 기능의 문서를 읽는다.** `docs/features/` 를 열어 이름으로 고른다. 코드 구조와 1:1 이
   아니다 — 한 기능이 여러 모듈에 걸치고 한 모듈이 여러 기능에 걸린다.
2. **그 문서의 교차 규칙에 적힌 다른 기능 문서도 읽는다.** 공백은 거의 전부 교차에서 나온다.
   한 기능 안에서 끝나는 변경은 애초에 문서를 틀리게 만들지 않는다.
3. **전제와 의도된 제약을 한 줄씩 대조한다.**

처분:

- **문장이 틀려졌다** → 고치기 전에 `docs/AGENTS.md` 의 가늠자를 적용한다. *기능을 고쳤는데
  그 문장이 틀렸다면 처음부터 거기 있을 게 아니었다* — 동작 서술이면 고치지 말고 **지운다.**
- **전제와 부딪친다** → 코드가 아니라 기획이 흔들린 것이다. **임의로 확정하지 않고 묻는다.**
- **열린 질문이 해소됐다** → 그 항목을 지우고 정해진 것을 제약으로 올린다.
- **새 공백이 생겼다** → 열린 질문으로 적는다.

## 6. `docs/` 가 바뀌었다면 — 기능 문서 게이트

```bash
git diff $BASE -- 'docs/*'
```

판정 기준은 `docs/AGENTS.md` 다. 추가된 문장마다 그 문서의 **"적지 않는다"** 를 적용한다.
자주 자라는 쪽:

- **동작 서술** — 화면에 무엇이 보이고 어떤 순서로 도는지. 코드가 말하고 커밋마다 어긋난다.
- **다른 문서 참조** — 번호나 절로 가리키면 항목이 늘거나 줄 때 깨진다. 필요한 사실은 그 한
  줄을 여기에도 적는다.
- **다른 기능과의 비교** — "저쪽은 이렇게 하는데 여기는 다르다" 는 저쪽이 바뀔 때 틀려진다.
  각자의 이유만으로 완결되게 쓴다.
- **이 프로젝트의 클래스명·파일명·패키지 경로.** 단 **OS 가 강제하는 제약은 플랫폼 API 이름을
  적는다** — 없으면 읽는 사람이 매번 다시 조사한다.

그리고 두 가지를 가른다:

- **의도된 제약인가 별도 절인가.** 다르게 정할 수 있었던 것은 제약 한 줄, OS·구조가 강제한
  것은 절이다. 절을 남발하면 제약 목록이 가벼워 보인다.
- **결정인가 판단을 미뤄 둔 것인가.** 둘 다 "지금 이렇게 동작한다" 지만, 미뤄 둔 것을 제약으로
  적으면 영구 상태로 굳고 결정을 열린 질문에 두면 끝난 논의가 다시 열린다.

## 처분 보고

고친 뒤, 항목마다 한 줄로 보고한다 — `파일:줄 — 무엇이 걸렸는지 → 처분(삭제/일반화/이전)`.
걸린 게 없는 게이트는 "0건" 이라고 말한다. **훑지 않은 게이트를 0건이라고 하지 않는다.**

## 완료 확인

1. §1 의 사라진 이름·옛 경로 Grep 이 전부 0건.
2. §2 의 시간·상태 표현과 문서가 가리키는 대상을 **전부 확인**(0건이 아니라 확인 완료가 기준).
3. §3 의 남은 주석이 모두 §6 의 네 범주 중 하나.
4. §4 의 `AGENTS.md` 추가 줄이 모두 "아키텍처 변경 없이는 틀려질 수 없다" 를 통과.
5. §5 — 동작을 바꿨으면 그 기능과 **교차 기능의 문서까지 읽고** 대조했다. 건드리지 않았으면
   건너뛰었다고 말한다.
6. §6 의 `docs/` 추가 줄이 모두 `docs/AGENTS.md` 의 "적는다" 에 속한다.
7. 한글을 고친 파일에 U+FFFD(regex `\x{FFFD}`) 0건 — 루트 §5.
8. 주석·문서만 고쳤어도 **루트 §6** 판정이 코드를 옮겼다면 변경 모듈을 컴파일한다.
