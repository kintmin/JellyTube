# 멤버를 지키지 않는 와일드카드 keep 규칙과, 그것을 보고 사람이 내린 판정.
#
# `-keep class * implements X` 는 R8 full mode 에서 클래스만 남기고 **기본 생성자를 지키지
# 않는다.** 그 클래스를 리플렉션으로 만든다면 생성이 조용히 실패한다. 규칙 자체가 버그는 아니다 —
# 생성자를 부르는 코드가 따로 있으면 멀쩡하다. 그래서 자동으로 판정하지 않고, 목록이 달라지면
# 빌드를 멈춰 사람이 보게 한다. 규칙마다 바로 위에 `# 판정:` 줄이 있어야 하고, 없으면 실패한다.
#
# 규칙의 출처는 R8 설정에서 그 줄 위의 `# ... section is <라이브러리>` 주석으로 본다:
#   android/app/build/outputs/mapping/release/configuration.txt
#
# `-keepnames` 와 `allowshrinking` 이 붙은 규칙은 "살아남으면" 을 전제로 한 다른 관용구라
# 여기 범위가 아니다.

# 출처: androidx.versionedparcelable:versionedparcelable:1.1.1
# 판정: 무해. 리플렉션으로 찾아지는 당사자는 구현체가 아니라 `<클래스명>Parcelizer` 이고, 같은
#   파일의 `-keep public class androidx.**Parcelizer { *; }` 가 그쪽을 멤버까지 지킨다. 생성된
#   Parcelizer.read() 가 구현체의 기본 생성자를 바이트코드에서 직접 부르므로, 구현체 생성자는
#   이 규칙이 아니라 살아 있는 코드에서의 참조로 지켜진다.
-keep class * implements androidx.versionedparcelable.VersionedParcelable

# 출처: com.google.firebase:firebase-components:16.1.0
# 판정: 위험. 이 규칙만으로는 레지스트라의 기본 생성자가 지워져 ML Kit 컴포넌트가 하나도 등록되지
#   않는다(릴리스에서 가사 번역이 통째로 죽었다). firebase-components 19.0.0 이 자기 규칙에
#   `{ void <init>(); }` 를 더해 고쳤지만 여기 해석되는 버전은 16.1.0 이라, proguard-rules.pro
#   에서 멤버를 지키는 같은 규칙으로 덮어 두었다. 전이 버전이 올라가도 우리 규칙이 남는다.
-keep class * implements com.google.firebase.components.ComponentRegistrar

# 출처: io.ktor:ktor-utils-jvm:3.6.1
# 판정: 위험하지만 지금은 닿지 않는다. Ktor 는 엔진을 안 고르면 ServiceLoader 로
#   HttpClientEngineContainer 구현을 찾는데, 이 규칙이 멤버를 안 지켜 AndroidEngineContainer 와
#   CIOEngineContainer 의 기본 생성자가 실제로 지워져 있다. HttpClientFactory 가
#   `HttpClient(Android)`·`HttpClient(CIO)` 로 엔진을 명시해 그 경로를 타지 않을 뿐이다.
#   엔진 없이 `HttpClient { }` 를 쓰는 순간 깨진다.
-keep class io.ktor.client.engine.** implements io.ktor.client.HttpClientEngineContainer
